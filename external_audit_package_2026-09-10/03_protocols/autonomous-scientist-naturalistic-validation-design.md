# Naturalistic validation design for the authority-separated Scientist

Status: pre-implementation design, written before any confirmatory outcome. This
document creates no evidence claim, task seed, hidden evaluation or execution
authorization. It is a separate ecological-validation layer and does not amend the
frozen primary estimand or analysis.

## Purpose

Test whether the scientific-control treatment can support externally meaningful
computational research rather than only closed causal assays. The study is
descriptive and is intended to strengthen ecological validity for editorial
review. It cannot rescue a failed primary study.

## Case-study domains

### Verified program optimization

An independent curator supplies a baseline program, formal semantics, permissible
transformation language, public training workloads and a sealed evaluation suite.
A valid advance is a previously unregistered transformation or search policy that
passes machine-checked semantic equivalence and improves the preregistered held-out
cost metric without protected-regime regression.

### Database or systems optimization

An independent curator supplies a pinned database/runtime environment, baseline
configuration or optimizer, public workload slice and sealed workload slice. A
valid advance must preserve query or system outputs and improve the preregistered
held-out latency/cost objective across repeated runs. Infrastructure variance and
measurement floors are specified before launch.

### Small-model reasoning and tool use

An independent curator supplies a pinned model, training budget, public development
set and sequestered held-out suite. A valid advance is a training, representation
or tool policy that improves the declared target capability while meeting
retention, leakage, format and compute controls. The previous cognitive-core
history and its outcomes are excluded.

## Three-arm execution

Each mission is run by:

1. a free monolithic instance of the same foundation model;
2. a prompt-equated monolithic instance receiving the same scientific obligations;
3. the authority-separated Scientist.

Public starting files, model snapshot, tool permissions, total model tokens,
wall-clock time, accelerator time and external search access are matched. The arm
order is provider-randomized. Scientific state, failures, compute and interventions
are ledgered. No arm can inspect another arm's work during execution.

Unlike the closed-world primary panel, naturalistic missions can have no successful
solution. A justified negative result counts only when the curator's contract
declares the discriminating evidence or exhaustion condition in advance. Producing
a plausible manuscript or improving a development metric alone is not a valid
advance.

## Evaluation and blinding

Each terminal package is normalized to remove arm identity. A deterministic
evaluator first checks executable correctness, held-out performance, budget,
provenance and declared safeguards. At least two domain experts then assess whether
the surviving claim is scientifically meaningful and whether the novelty search
supports the stated boundary. Disagreements and all negative evaluations are
retained. The strongest surviving result is independently rerun from the released
package by a party that did not curate or execute the mission.

## Proposed success condition

The ecological layer is compelling enough for the Nature narrative only if:

- the Scientist has no unsupported promotion in any case;
- it is non-inferior to both controls in every case on the binary valid-advance
  endpoint;
- it produces at least one valid advance not produced by either control; and
- at least one such Scientist-only advance reproduces independently.

Because the case count is small, report exact cases and costs without an
inferential population claim. The primary 180-task panel remains the only efficacy
estimand.

## Required work before this becomes a protocol

1. Obtain one independent curator and one independent validator for each domain.
2. Pin executable environments and machine-checkable endpoint schemas.
3. Define budgets after a blinded feasibility calibration that is excluded from
   the cases.
4. Implement a common three-arm ledger and fail-closed interruption policy without
   changing the already frozen primary implementation.
5. Freeze every domain package, prompt, scorer, budget and analysis before curators
   reveal the live missions or held-out evaluations.
6. Archive a signed commitment proving temporal order and separation.
